# Auto 3D for product images

Admins upload a product photo; the store can turn it into a 3D model (GLB) shown with `<model-viewer>` on the product page.
Without any setup the store still works: you get an **on-device "tilt" preview** of the photo (labelled "Preview 3D (on-device)").

## Modes

| Mode | When | What `request3D` does |
|---|---|---|
| Local | `SUPABASE_URL`/`SUPABASE_ANON_KEY` empty in `js/config.js` | Job finishes instantly. Adds a `model3d` item with `url: null`, `fallback: 'tilt'`, `source: 'generated'`. Files are stored in IndexedDB (`jps_media`). |
| Supabase, no provider key | Supabase configured, `MESHY_API_KEY` not set | Row in `product_3d_jobs`, Edge Function finishes it at once with the same tilt fallback. |
| Supabase + Meshy | `MESHY_API_KEY` set | Real image-to-3D. Result GLB is copied to Storage `product-media/models/<product>/<job>.glb` and added to `products.media` (`fallback` absent, `url` = GLB). |

Knobs in `js/config.js` (public, no secrets): `AUTO_3D` (default `true`; set `false` to stop automatic jobs on every image upload),
`MEDIA_LIMITS` (`image` 8 MB, `video` 50 MB, `model3d` 30 MB), `MEDIA_BUCKET` (`product-media`), `FUNCTION_3D` (`generate-3d`).

## One-time setup (Supabase)

1. Run `sql/schema.sql` in the SQL editor (fresh project) **or** `sql/migrations/002_media_3d_settings.sql` (existing project).
   This adds `products.media`, `profiles.preferences`, `product_3d_jobs`, the public `product-media` bucket
   (50 MB cap, MIME allow-list jpeg/png/webp/mp4/webm/glb) and admin-only write policies.
2. Install the Supabase CLI, `supabase login`, `supabase link --project-ref <ref>`.
3. Set secrets (never commit them, never put them in `js/config.js`):
   ```
   supabase secrets set MESHY_API_KEY=msy_xxxxxxxx
   supabase secrets set MESHY_MODEL=meshy-6          # optional, default meshy-6
   supabase secrets set WEBHOOK_TOKEN=$(openssl rand -hex 24)   # optional, only if you configure a provider webhook
   supabase secrets set PROVIDER_3D=meshy            # optional, default meshy
   ```
   `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY` are injected automatically.
4. Deploy: `supabase functions deploy generate-3d --no-verify-jwt`
   (`--no-verify-jwt` is needed only so the optional webhook can call it; the function itself rejects anyone who is not an
   admin JWT or the webhook token.)
5. Fill `SUPABASE_URL` and `SUPABASE_ANON_KEY` in `js/config.js`, sign up on the site, then promote yourself
   (`update public.profiles set is_admin = true where email = '...'`).

## How a job runs

`uploadMedia(image)` -> `product_3d_jobs` row `queued` -> function `advance`: atomically claims the job (`processing`), creates the
Meshy task (`POST /openapi/v1/image-to-3d`, `ai_model`, `should_texture`, `enable_pbr`) -> the browser (`get3DJob` / `list3DJobs`,
throttled to one nudge per 5 s per job) and/or the webhook call `advance` again, which polls
`GET /openapi/v1/image-to-3d/{id}` -> on `SUCCEEDED` the GLB is downloaded (max 30 MB, `glTF` magic checked), uploaded to Storage and attached
via `apply_generated_model` -> job `succeeded`. Failures set `status: 'failed'` with `error`. Jobs older than 1 h are failed.
Polling only advances while an admin has the page open (or the webhook is configured); there is no cron.

## Swapping provider

`supabase/functions/generate-3d/index.ts` has a `Provider` interface (`configured`, `supports`, `createTask`, `getTask`).
Implement another one (e.g. Tripo), add it to `providers`, set `PROVIDER_3D`.

## Cost and latency caveats

- Meshy is **paid per task** (credits; check your plan on meshy.ai/api and its pricing page: the API needs a paid plan and
  textured meshy-6 tasks cost more credits than untextured ones). Each uploaded image triggers one task, and "Regenerate"
  triggers another. Turn `AUTO_3D` off if you upload many photos; use the "Generate 3D" button selectively.
- Typical latency is a few minutes per model; the queue can be slower under load. The UI should show `queued/processing + progress`.
- Meshy requires a publicly reachable **JPEG or PNG** source URL (WebP sources are failed with a clear error). Product-media is
  a public bucket, so this works out of the box. Meshy result URLs are signed and expire (retained about 3 days on non-Enterprise
  plans), which is why the GLB is copied into your own bucket.
- Quality: single-photo 3D guesses the back side; flat items (flags, scarves, stickers) look best with the tilt preview.
- Storage egress/size: GLBs are typically 2-20 MB; the function rejects results over 30 MB.
- Rate limits and concurrency depend on the Meshy plan; failures surface as `failed` jobs and can be retried via "Regenerate".

## Not verified here

The Edge Function and SQL have not been run against a live Supabase project or the live Meshy API (no keys or network in the
dev environment); the Meshy request/response shapes follow Meshy's published docs. Test with one image first.
